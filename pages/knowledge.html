IEEE 802.11 é a família de padrões que define as comunicações em redes locais sem fio (WLAN). Cada letra representa uma geração:

  • 802.11a (1999) — 5 GHz, até 54 Mbps
  • 802.11b (1999) — 2.4 GHz, até 11 Mbps
  • 802.11g (2003) — 2.4 GHz, até 54 Mbps
  • 802.11n / Wi-Fi 4 (2009) — Dual-band, até 600 Mbps, MIMO
  • 802.11ac / Wi-Fi 5 (2014) — 5 GHz, até 6.9 Gbps, MU-MIMO
  • 802.11ax / Wi-Fi 6/6E (2020) — Dual/Tri-band, OFDMA, até 9.6 Gbps

Para pentest, trabalhamos principalmente com os frames de gerenciamento (management), controle (control) e dados (data) do protocolo 802.11.

WEP (1997) — Totalmente quebrado. Usa RC4 com IVs de 24 bits. Crackeável em minutos com aircrack-ng. Nunca use.

WPA (2003) — Medida temporária. Usa TKIP (ainda baseado em RC4). Vulnerável a ataques de fragmentação.

WPA2 (2004) — Padrão atual mais comum. Usa AES-CCMP. Vulnerável a captura de handshake + brute force offline e ataque PMKID.

WPA3 (2018) — Mais seguro. Usa SAE (Simultaneous Authentication of Equals) em vez de PSK. Resistente a ataques de dicionário offline. Ainda possui vulnerabilidades como Dragonblood.

O handshake de 4 vias é o processo de autenticação entre cliente e AP no WPA2:

  1. MSG 1: AP envia ANonce (número aleatório) ao cliente
  2. MSG 2: Cliente gera PTK usando ANonce + SNonce + PMK e envia SNonce + MIC ao AP
  3. MSG 3: AP verifica MIC, gera GTK e envia ao cliente
  4. MSG 4: Cliente confirma e a conexão é estabelecida

Por que capturamos isso? A MSG 2 contém o MIC (Message Integrity Code) que é derivado da senha. Com o handshake, podemos testar senhas offline comparando o MIC calculado com o capturado.

The 4-way handshake is the authentication process between client and AP in WPA2:

  1. MSG 1: AP sends ANonce (random number) to client
  2. MSG 2: Client generates PTK using ANonce + SNonce + PMK and sends SNonce + MIC to AP
  3. MSG 3: AP verifies MIC, generates GTK and sends to client
  4. MSG 4: Client confirms and connection is established

Why do we capture this? MSG 2 contains the MIC (Message Integrity Code) derived from the password. With the handshake, we can test passwords offline by comparing the calculated MIC with the captured one.

PMKID = Pairwise Master Key Identifier. É um valor calculado pelo roteador usando:

PMKID = HMAC-SHA1-128(PMK, "PMK Name" || MAC_AP || MAC_STA)

Em 2018, Jens "atom" Steube descobriu que muitos roteadores enviam o PMKID no primeiro frame de associação (RSN IE), antes mesmo do handshake completo. Isso significa que:

  • Não precisamos de nenhum cliente conectado
  • Não precisamos capturar o handshake de 4 vias
  • Basta enviar uma solicitação de associação ao AP
  • A captura leva apenas 1-5 minutos

Modo Gerenciado (Managed) — Modo padrão. A placa só processa pacotes destinados ao seu endereço MAC ou broadcast. É o modo normal para navegar na internet.

Modo Monitor — A placa captura TODOS os frames 802.11 no ar, independente do destino. Essencial para sniffing e injeção de pacotes. Nem todas as placas suportam — chipsets recomendados: Atheros AR9271, Ralink RT3070, Realtek RTL8812AU.

Managed Mode — Default mode. The card only processes packets addressed to its MAC or broadcast. Normal mode for internet browsing.

Monitor Mode — The card captures ALL 802.11 frames in the air, regardless of destination. Essential for sniffing and packet injection. Not all cards support it — recommended chipsets: Atheros AR9271, Ralink RT3070, Realtek RTL8812AU.

Management Frames — Gerenciam conexões: Beacon (AP anuncia existência), Probe (cliente busca redes), Authentication, Association, Deauthentication (usado no ataque deauth!).

Control Frames — Controlam acesso ao meio: ACK, RTS/CTS. Não carregam dados.

Data Frames — Transportam dados reais dos usuários (HTTP, DNS, etc.). São os frames criptografados em WPA2.

Estratégias:

  • Dicionário puro: Testa cada palavra da lista

  • Máscara: Brute force com padrão definido (?d?d?d?d = 4 dígitos)
  • Híbrido: Combina dicionário + máscara (palavra + 4 dígitos)

Strategies:

  • Pure dictionary: Tests each word from the list
  • Rules (Hashcat): Modifies each word (adds numbers, swaps letters)
  • Mask: Brute force with defined pattern (?d?d?d?d = 4 digits)
  • Hybrid: Combines dictionary + mask (word + 4 digits)

Durante a varredura (scanning), as portas abertas indicam quais serviços estão escutando conexões. As mais comuns incluem:

  • FTP (Porta 21): Transferência de arquivos. Comum encontrar login anônimo ativado.
  • SSH (Porta 22): Acesso remoto seguro à console Linux. Alvo principal de brute force.
  • HTTP/HTTPS (Portas 80/443): Servidores web. Alvo de Gobuster, SQLmap, XSS e Burp Suite.
  • SMB (Porta 445): Compartilhamento de arquivos Windows. Muito visado por exploits (ex: EternalBlue).
  • RDP (Porta 3389): Acesso remoto de área de trabalho do Windows.

During scanning, open ports reveal which network services are listening. The most common include:

  • FTP (Port 21): File transfer. Often configured with anonymous login enabled.
  • SSH (Port 22): Secure shell for Linux remote console. Primary target for brute forcing.
  • HTTP/HTTPS (Ports 80/443): Web servers. Target for Gobuster, SQLmap, XSS, and Burp.
  • SMB (Port 445): Windows file sharing. High-value target for remote exploits (e.g., EternalBlue).
  • RDP (Port 3389): Windows Remote Desktop Protocol.

SQL Injection (SQLi) é uma vulnerabilidade onde comandos SQL maliciosos são inseridos em campos de entrada de dados de uma aplicação web e repassados diretamente para o banco de dados sem validação.

Como previnir: A melhor defesa é o uso de Prepared Statements (consultas parametrizadas) e ORMs modernos, garantindo que a entrada do usuário seja tratada como dado e nunca como instrução executável SQL.

SQL Injection (SQLi) is a critical vulnerability where malicious SQL statements are injected into entry fields of web applications and executed directly by the database engine without validation.

How to prevent: The best defense is using Prepared Statements (parameterized queries) and modern ORMs, ensuring user input is treated as raw data rather than executable code.

Ao explorar um sistema vulnerável, queremos obter controle do terminal do alvo. Há duas formas principais:

  • Reverse Shell (Shell Reverso): O alvo conecta de volta para a máquina do invasor. Ideal para contornar firewalls locais que bloqueiam conexões de entrada.
  • Bind Shell: O exploit abre uma nova porta de escuta no alvo, e o invasor se conecta diretamente nela. Pode ser bloqueado por firewalls se a porta aberta for incomum.

When exploiting a vulnerable host, we seek access to the target command line. There are two main methods:

  • Reverse Shell: The target connects back to the attacker's machine. Highly effective for bypassing firewall rules blocking inbound connections.
  • Bind Shell: The exploit opens a new listener port directly on the target host. Attackers connect directly to it. Often blocked by network firewalls.

O Active Directory (AD) gerencia a infraestrutura de identidades do Windows no ambiente empresarial. Pentests corporativos focam fortemente em AD devido a ataques de movimentação lateral e escalada de privilégios.

Ataques Comuns: Kerberoasting (coleta de hashes de serviço), Pass-the-Hash (uso do hash NTLM direto para autenticar sem decifrar a senha) e envenenamento LLMNR (captura de hashes na rede com o Responder).

Active Directory (AD) manages identity and access controls in enterprise Windows networks. Corporate pentests focus heavily on AD security to identify lateral movement routes and privilege escalation paths.

Common AD Attacks: Kerberoasting (collecting service ticket hashes), Pass-the-Hash (using captured NTLM hashes directly to authenticate without cracking), and LLMNR poisoning (intercepting network hashes using Responder).

Em laboratórios de redes, o Wireshark permite descriptografar tráfego WPA2 capturado para fins de auditoria e diagnóstico.

Parâmetros Necessários:

  • SSID: O nome da rede sem fio (essencial para gerar o sal do hash).
  • Senha (WPA-pwd) ou PMK: A chave pré-compartilhada da rede.
  • Handshake de 4 vias (EAPOL): Os frames de conexão inicial do dispositivo alvo.

Como Funciona a Decodificação:

O Wireshark usa o SSID e a Senha para derivar a **PMK** (Pairwise Master Key). Em seguida, ele analisa o handshake EAPOL capturado para extrair o **ANonce** (do AP) e o **SNonce** (do cliente). Combinando estes parâmetros com os endereços MAC de ambos, ele reconstrói a chave temporária daquela conexão (**PTK**), permitindo a descriptografia de todos os pacotes de dados subsequentes.

Configuração no Wireshark:

1. Vá em Edit → Preferences → Protocols → IEEE 802.11.
2. Marque a opção "Enable decryption".
3. Clique em Decryption Keys (Edit) e adicione uma chave do tipo wpa-pwd com o formato: senha:SSID (exemplo: minhasenha123:RedeLaboratorio).

In networking labs, Wireshark allows decrypting captured WPA2 traffic for auditing and troubleshooting purposes.

Required Parameters:

  • SSID: The wireless network name (required for hashing salt).
  • Password (WPA-pwd) or PMK: The pre-shared key of the network.
  • 4-Way Handshake (EAPOL): The initial connection frames of the target device.

How Decryption Works:

Wireshark uses the SSID and Password to derive the **PMK** (Pairwise Master Key). It then scans the EAPOL handshake to extract the **ANonce** (from the AP) and the **SNonce** (from the client). Combining these values with the MAC addresses, it reconstructs the session key (**PTK**), decrypting all subsequent data packets.

Configuration in Wireshark:

1. Open Edit → Preferences → Protocols → IEEE 802.11.
2. Check the "Enable decryption" box.
3. Click Decryption Keys (Edit) and add a key of type wpa-pwd using the format: password:SSID (example: mypassword123:LabNetwork).

  • ✅ Use WPA3 se disponível, ou WPA2 com AES (nunca TKIP)
  • ✅ Senha forte: 12+ caracteres com letras, números e especiais
  • ✅ Desative WPS completamente no roteador
  • ✅ Use 802.11w (Management Frame Protection) contra deauth

  • ✅ Use MAC filtering como camada extra (não como única defesa)
