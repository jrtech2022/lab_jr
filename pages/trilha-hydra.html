Fase 1

Confirmar o Serviço AtivoConfirm Active Service

Ataques de brute force online geram muito ruído de rede e logs no sistema. Só realizamos o ataque após confirmar que o serviço (ex: SSH na porta 22, FTP na 21) está ativo usando o Nmap. Online brute force attacks generate network noise and log entries. We only launch the attack after verifying the targeted service (e.g., SSH on port 22, FTP on 21) is active using Nmap.

Confirmar porta SSHVerify SSH Port
nmap -p 22 192.168.1.100
Fase 2

Brute Force SSH (Usuário Fixo)Brute Force SSH (Single User)

Se suspeitamos de um usuário específico (ex: root), usamos a flag -l (minúsculo) para fixar o login e -P (maiúsculo) para a lista de senhas. If we target a specific user (e.g., root), we use the -l flag (lowercase) to fix the login, and -P (uppercase) for the password wordlist.

Hydra SSH
hydra -l admin -P /usr/share/wordlists/rockyou.txt ssh://192.168.1.100 -t 4 -V
Desempenho: Use o parâmetro -t para controlar o número de threads (conexões simultâneas). Para SSH, evite passar de 4 para não derrubar o serviço ou ser bloqueado imediatamente.Performance: Use -t to limit tasks (concurrent connections). For SSH, avoid going above 4 to prevent service crashes or immediate locking.
Fase 3

Ataque FTP (Multi-Usuários)FTP Attack (Multi-Users)

Se não sabemos o nome do usuário, passamos uma lista (wordlist) de logins usando a flag -L (maiúsculo). Serviços como FTP lidam melhor com mais threads. If we do not know the user names, we supply a wordlist of usernames using the -L flag (uppercase). Protocols like FTP handle higher concurrency well.

Hydra FTP
hydra -L users.txt -P /usr/share/wordlists/rockyou.txt ftp://192.168.1.100 -t 16 -vV
Fase 4

Mitigação e SegurançaMitigation & Hardening

Ataques de brute force online são fáceis de mitigar. Melhores práticas defensivas incluem desativar autenticação por senhas (usando chaves criptográficas SSH no lugar), alterar portas padrão e instalar ferramentas de bloqueio automático como Fail2ban. Online brute force attacks are easy to mitigate. Best hardening practices include disabling password login (using SSH keypairs instead), changing default ports, and installing automated lockout software like Fail2ban.
