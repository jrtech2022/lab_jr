Trilha Web Auditing (Gobuster & SQLmap)Web Auditing Trail (Gobuster & SQLmap)

Aplicações web são os principais vetores de entrada em corporações. Nesta trilha, aprenderemos a mapear caminhos ocultos em um servidor e a extrair o banco de dados via vulnerabilidade de SQL Injection. Web applications are major entry vectors in enterprise networks. In this trail, we'll learn to map hidden paths on a server and extract database contents via SQL Injection vulnerabilities.

Fase 1

Mapear Diretórios (Gobuster)Directory Discovery (Gobuster)

Desenvolvedores frequentemente deixam arquivos ou painéis administrativos ocultos. Usamos o gobuster com uma wordlist para testar milhares de caminhos web comuns e localizar páginas de login ou diretórios ocultos. Developers often leave hidden files or administrative portals. We use gobuster with a wordlist to test thousands of common web paths and locate hidden login pages or directories.

Comando de ReconhecimentoScan Command
gobuster dir -u http://192.168.1.100/index.php?id=1 -w /usr/share/wordlists/dirb/common.txt
Fase 2

Detectando Vulnerabilidade SQLiDetecting SQLi Vulnerability

Se um formulário ou parâmetro de URL não filtra a entrada do usuário, comandos SQL podem ser injetados. Primeiro, testamos se o parâmetro (ex: ?id=1) é vulnerável inserindo caracteres de aspas simples ('). Se a página der erro interno de SQL, a falha existe! If an input form or URL parameter does not filter user input, SQL commands can be injected. First, we test if the parameter (e.g., ?id=1) is vulnerable by inserting single quotes ('). If the page returns a database error, the vulnerability exists!

Confirmar Vulnerabilidade com SQLmapConfirm Vulnerability with SQLmap
sqlmap -u "http://192.168.1.100/index.php?id=1" --batch
O parâmetro --batch responde automaticamente com as opções padrão, facilitando a automação rápida do escaneamento do SQLmap.The --batch flag automatically accepts the default options, making fast automation of SQLmap scans easier.
Fase 3

Mapeando os Bancos de DadosMapping Databases

Com a falha confirmada, pedimos ao SQLmap para listar os bancos de dados acessíveis usando o parâmetro --dbs. With the vulnerability confirmed, we ask SQLmap to list all accessible databases using the --dbs flag.

Mapear BancosMap Databases
sqlmap -u "http://192.168.1.100/index.php?id=1" --dbs --batch
Fase 4

Dump de CredenciaisDumping Credentials

Após identificar o banco correto (ex: security ou wordpress), localizamos tabelas sensíveis de usuários e realizamos o dump das credenciais (usando --dump). O SQLmap tentará decifrar os hashes de senhas locais. After identifying the correct database (e.g., security or wordpress), we target sensitive user tables and dump the credentials (using --dump). SQLmap will also attempt to crack hashed passwords.

Dump Users
sqlmap -u "http://192.168.1.100/index.php?id=1" -D security -T users --dump --batch
